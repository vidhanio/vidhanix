# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`vidhanix` is a personal NixOS + Home Manager configuration built as a **[dendritic](https://github.com/mightyiam/dendritic)** flake. There are two hosts: `vidhan-pc` (x86_64 desktop, CachyOS kernel) and `vidhan-macbook` (aarch64 Apple Silicon via nixos-apple-silicon).

## Common commands

- **Validate a change** (evaluate + build, do not activate): `git add -AN && nh os build`
  - The build reads **staged** files, so you must `git add -AN` (intent-to-add) first — unstaged changes are invisible to the build. This is the primary check to run after editing any `.nix` file (see the `nixos-build` agent skill in `.agents/skills/`).
- **Apply the config** (regenerate files + activate): `rebuild` (provided by the dev shell). Equivalent to `git add -AN && nix run .#generate-files && nh os switch`. Pass a different `nh os` subcommand as an argument, e.g. `rebuild boot`.
- **Format**: handled by `treefmt` and enforced as a pre-commit hook. Formatters: nixfmt, statix, deadnix, shfmt, shellcheck, stylua, actionlint, oxfmt, xmllint, keep-sorted. `on-unmatched = "fatal"`, so every non-ignored file must be claimed by some formatter.
- **Update packages**: `nix run .#update-packages` (all packages with an `updateScript`), or `nix run .#update-packages <name>...` for specific ones.
- **Regenerate generated files**: `nix run .#generate-files`.

The dev shell (auto-loaded via direnv / `.envrc`) provides `rebuild`, `nil`, `sops`, and the pre-commit hooks.

## Architecture

### Dendritic module layout

`flake.nix` is `mkFlake` over **`import-tree ./modules`** — every `.nix` file anywhere under `modules/` is automatically imported as a flake-parts module. There is no central import list; **adding a file to `modules/` is how you add a module.** Directory nesting is purely organizational.

Each file is a flake-parts module and typically contributes to one or more of:

- `flake.modules.nixos.<name>` — a NixOS module fragment
- `flake.modules.homeManager.<name>` — a Home Manager module fragment
- `perSystem.*` — packages, formatters, dev shell, etc.
- `flake-file.inputs.<name>.url` / `flake-file.nixConfig.*` — see "Generated files" below

The key idea: many small files across the tree each add a slice of config to the **same** named aggregate module (usually `default`). For example, `modules/programs/fish/*.nix` split fish config across `default.nix`, `prompt.nix`, `history.nix`, etc., all piling into `flake.modules.{nixos,homeManager}.default`.

### How a host is assembled

Aggregate → base → host:

1. **`default`** — the catch-all module everything contributes to. `flake.modules.nixos.default` and `flake.modules.homeManager.default` accumulate the bulk of the system.
2. **Bases** (`modules/systems/bases/`) — `desktop` and `macbook` each `import` `default` and layer platform-specific bits.
3. **Configurations** (`modules/systems/configurations/`) — `configurations.<host>` (a custom option defined in `configurations/default.nix`) imports a base and sets host-specific hardware/monitors/stateVersion. `configurations/default.nix` maps each `configurations.<host>` into `flake.nixosConfigurations.<host>`, wires up users, home-manager, and sops password secrets.

Users are declared in `modules/systems/users/` (`users.<name>` custom option with `fullName`/`email`/`publicKeys`/`module`); a host opts a user in via `configurations.<host>.users.<name>.enable`. SSH keys flow automatically between hosts and users through these options.

### Generated files — do not edit directly

Several tracked files carry a `@generated by nix run .#generate-files` header and **must not be hand-edited**:

- **`flake.nix`** — inputs and `nixConfig` are declared piecemeal as `flake-file.inputs.<name>.url = ...` and `flake-file.nixConfig.*` scattered across modules (via the `flake-file` input). Add/change a flake input by editing the module that needs it, then run `nix run .#generate-files`, never by editing `flake.nix`.
- **`README.md`, `.envrc`, `.gitignore`, `LICENSE`** — generated from `files.*` options (`modules/flake/files/`). The README package table is generated from package `meta.description` and `passthru.updateScript`.
- **`.pre-commit-config.yaml`** — a symlink into the Nix store.

### Secrets

Secrets use **sops-nix** with `secrets/secrets.yaml` (age keys derived from host SSH keys; recipients in `.sops.yaml`). Host password secrets are declared automatically per active user in `configurations/default.nix` with `neededForUsers = true`. SSH host keys live on the impermanence persistent path.

### Impermanence

Root is wiped on boot (tmpfs on desktop, a re-created btrfs subvolume on macbook). Anything that must survive reboot is declared via the `persist.*` alias options (`environment.persistence."/persist"` for NixOS, `home.persistence` for Home Manager) in the relevant module — see `modules/systems/disk/impermanence/`.
